# APM {VERSION} - Atlassian Guide

For the Planner and Manager. Check access per §1 before publishing the Spec and Plan to Confluence or working with Stage Epics in Jira.

## 1. Access

Use the direct tools and app-specific search for the agreed Confluence space and Jira project. Follow the tool descriptions to resolve the site and account. Before sharing, check the destination and audience. Share only material agreed for that audience. Keep credentials and personal setup out of Confluence, Jira and shared session records.

If you lack a tool or access, tell the User what is blocked and pause that action. Link the [Atlassian MCP setup guide](https://support.atlassian.com/atlassian-ai-gateway/docs/get-started-with-the-atlassian-remote-mcp-server/).

## 2. Publish the Spec, Plan and Stage Epics

When an ID or key is missing, search for the item in the agreed space or project before creating it. Reuse a confirmed match. After an uncertain create, check again before retrying. Search can lag. If the result is still unclear, tell the User what you checked and wait.

### 2.1 Confluence Pages

Publish to Confluence when a page's content or links change. Use the session name and document kind in each title. Save each confirmed page link and ID in its source document's Notes and update by that ID. Keep those fields in Markdown only. Link the Plan to the Spec. Once the Epics exist, link each from its Stage in the Plan and from relevant sections of the Spec. Check the pages and use source links the audience can open. Use page comments for review and apply agreed changes to Markdown. Reconcile unexpected page edits before replacing content.

### 2.2 Stage Epics

Update existing Epics by their saved keys. Use the session name and Stage number to identify each Epic. Leave new Epics unassigned and verify the result. As soon as a key is confirmed, link it in the Plan's Stages table. Add the Confluence Plan link to the Epic if missing. Keep assignment and status when updating Epic content.

## 3. Check or Update a Stage Epic

Teammates agree who will run a Stage before assigning themselves to an available, unassigned Epic in Jira. Keep that assignment through the Stage. Read the Epic by its key in the Plan and compare the assignee's account ID with the signed-in teammate's ID. Before taking over or dispatching, pause if the assignment differs or the status is neither claimable nor in progress. For a Stage already underway, require the in-progress status.

For a start, verify the claim before using the status from that read. For a close, an Epic already at the agreed complete status needs no further action. If a transition is still needed, confirm ownership, list the available transitions, apply the agreed one and verify the result. On an uncertain response, read the Epic before retrying. Pause dependent work if you cannot confirm the result.
